DATASET SPLIT ANALYSIS

Scope
This report distinguishes the original dataset from the processed dataset used
by the saved baseline model. No datasets, model files, or split assignments were
changed. Only this report was created.

Evidence examined
- metadata/dataset_manifest.csv: 2,181 original image-mask pairs.
- data/processed/lumen_baseline_256/processed_manifest.csv: 1,376 retained pairs.
- Original folder paths and filenames, plus the audit's exact pixel hashes.
- The current raw file inventory matches the manifest: 4,362 files.
- No non-PNG documentation or patient/case lookup files were found inside the
  raw dataset. Therefore filename meanings cannot be independently confirmed.

1. WHAT IDS CAN BE IDENTIFIED?

Test filenames contain apparent patient/case codes:
  p001_video_2_<frame>.png   -> apparent patient/case 001
  p006_video_1_<frame>.png   -> apparent patient/case 006
  p_003_video_<n>_<frame>.png -> apparent patient/case 003

The prefixes p001 and p_003 are normalized to the same naming convention, but
001 and 003 remain different IDs. The letter p plausibly means patient; this is
an inference from naming, not confirmation of three distinct people.

Test folder mapping:
  test/test_01: apparent ID 001, video 2, 100 images.
  test/test_02: apparent ID 006, video 1, 361 images.
  test/test_03: apparent ID 003, three videos, 505 images:
                video 1: 233; video 2: 160; video 3: 112.

Original train/validation names use video_3, video_4, video_5, video_6,
video_7_pt1, and video_7_pt2. They do not explicitly name patients or cases.
Both parts of video_7 are conservatively treated as one video group. A video
group is not necessarily a unique patient or a confirmed clinical case.

Training has one video group; validation has one different video group. This
must NOT be reported as one confirmed unique patient in each split. Patient or
case identities for these videos are missing from the available filenames.
Validation comprises 18 frames from video_7_pt1 and 81 from video_7_pt2.

No known source component or exact original-image pixel hash crosses the
current processed split boundaries. The processed manifest assigns:
  video_3 -> train
  video_7 -> validation
  apparent IDs 001, 003, 006 -> test

Conclusion for the CURRENT split:
It is separated by the identifiable video/source groups and deduplicated.
It is NOT a verified patient-level split. There is no observed shared explicit
patient ID across current splits, but training/validation patient identities
are unknown, so actual patient overlap cannot be ruled out.

Original train and validation each contain five base video groups (six named
segments when video_7 parts are counted separately). Every one of those base
video groups occurs in both train and validation. Their unique patient/case
counts cannot be determined from filenames alone.

Exact-image evidence also connects differently named recordings:
  video_4 <-> p_003_video_1: 233 matching image groups.
  video_5 <-> p_003_video_2: 160 matching image groups.
  video_6 <-> p_003_video_3: 112 matching image groups.

All 505 original video_4/5/6 images in train/validation have identical-image
counterparts under the test prefix p_003. This strongly links those recordings
to apparent ID 003, despite the different filenames. On that evidence, apparent
ID 003 is represented in ALL THREE original splits: 302 train images, 203
validation images, and 505 test images. Its underlying identity remains subject
to confirmation of the dataset's naming convention.

Thus the ORIGINAL train and validation each have at least one identifiable
apparent patient/case by duplicate linkage (003), plus two video groups with
unresolved identity (video_3 and video_7). The total unique patient/case count
in either split remains unknown. The original test set has three apparent IDs.

Original cross-split exact-image duplication:
  Train + test:       302 duplicate groups.
  Validation + test:  203 duplicate groups.
  Train + validation:  2 duplicate groups.
  Total:             507 groups involving 1,015 image records.

Conclusion for the ORIGINAL split:
Train/validation are image/frame-level partitions of shared videos, not
patient-independent partitions. Test folders appear organized by patient/case,
but copied frames from apparent ID 003 occur in train/validation. Therefore the
original three-way partition is not patient-level and has confirmed leakage.

4. LEAKAGE RISK AND SIMPLE INTERPRETATION

The original arrangement let the model see the same pictures, and other frames
from the same recordings, on both sides of an evaluation split. That can make
scores look better than performance on genuinely new patients.

The current preprocessing removed those known overlaps. This analysis found
zero cross-split exact-image duplicate groups in the processed manifest, and
the identifiable source groups are separated. The baseline used these processed
splits, not the original overlapping partition.

Residual risk remains: different video names could still belong to the same
patient or procedure. Without patient/case mappings for video_3 and video_7,
we cannot prove that training, validation, and test represent different patients.
Exact duplicate checks also do not rule out every differently encoded or
near-duplicate frame from an unidentified source.

Training and validation each rely on only one named video group. Frames within
a recording are correlated, so hundreds of frames do not represent hundreds of
independent patients. This limits conclusions about generalization even if a
future patient lookup confirms there is no overlap.

Before claiming patient-level evaluation, obtain the dataset's video-to-patient
and video-to-case mapping (particularly for video_3 and video_7). A future split
should keep all recordings from the same patient together. No such reorganization
or retraining was performed for this analysis.
