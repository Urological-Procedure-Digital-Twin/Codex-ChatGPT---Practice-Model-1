VERSION 2: TRAINING AUGMENTATION EXPERIMENT

Question: Does conservative training-data augmentation improve generalization?

CONTROLLED SETTINGS
The original SmallUNet architecture (121,177 parameters), BCE + soft Dice loss,
Adam settings (learning rate 0.001 and all other optimizer options), gradient
clipping, batch size 4, seed 42, deterministic settings, normalized inputs,
splits, metrics, and probability threshold 0.5 were retained.
Version 2 started from the same seeded initialization, not the trained baseline.
Both experiments completed 8 epochs. The original baseline's early stopping did
not trigger; Version 2 explicitly runs the requested full 8-epoch budget.
Checkpoint selection remained highest validation Dice, with no test-based tuning.

Split sizes stayed 311 training / 99 validation / 966 test. The processed
manifest hash and the exact test sample IDs match the baseline. Validation and
test use the original LumenDataset without augmentation. Original files and
processed arrays are never rewritten by the experiment.

ONLY EXPERIMENTAL CHANGE: TRAINING INPUT AUGMENTATION
Fresh random transforms are sampled when a training sample is loaded:
1. Rotation: uniformly between -7.5 and +7.5 degrees. The same angle, center,
   canvas, and zero fill are applied to the image and mask. Images use bilinear
   interpolation; masks use nearest-neighbor interpolation and remain {0,1}.
   No canvas expansion is used, so small edge regions may be clipped.
2. Brightness: multiply by a random factor from 0.9 to 1.1, image only.
3. Contrast: use a random factor from 0.9 to 1.1, image only.
4. Blur: 20% probability of Gaussian blur with radius from 0.3 to 0.7 pixels,
   image only. Masks are never blurred or photometrically transformed.

The order is rotation, brightness, contrast, then optional blur. Pillow operates
on the RGB image's 8-bit representation, and the result is converted back to
float32 [0,1]. There are no flips, additional crops, or other transformations.
An independent seeded Python RNG handles augmentation so it does not consume
the model's RNG or the DataLoader's shuffle RNG.

VALIDATION BEFORE AND AFTER TRAINING
Synthetic paired-geometry tests passed, including binary-mask preservation.
Repeated augmentation streams were reproducible and left global RNGs unchanged.
An 8-training/4-validation-sample, one-epoch smoke test passed before the full run.
It exercised checkpoint saving/reloading and evaluated validation only.
After training, architecture shapes, complete optimizer parameter-group settings,
seed, batch size, input manifest, split sizes, threshold, and epoch counts were
compared against the baseline. All checks passed. Baseline checkpoint and
original configuration/history/summary hashes were unchanged.

DIRECT COMPARISON
Both best checkpoints were evaluated on the same untouched validation/test
loaders. Re-evaluated baseline metrics agreed with the original results.

INTERPRETATION
Augmentation improved performance on this test set: Dice increased by about
8.65 percentage points and IoU by 6.76 percentage points. It did not improve
validation performance: Dice decreased by 2.28 points and IoU by 2.24 points.
Therefore the result is mixed evidence for improved generalization, not a
consistent improvement across both held-out splits.

This is one controlled seed/run with a small patient sample. Training represents
Patient 2 and validation Patient 4 under the supplied publication mapping. The
p_003 test group is associated with Patient 3; p001/p006 mappings remain
unverified. Correlated video frames and those mapping uncertainties limit broad
claims. No statistical significance or improvement on all future patients is
established. The test set has already been examined in prior analysis, so this
is an exploratory comparison rather than a fresh final external validation.
No augmentation settings or other hyperparameters were revised after seeing
these results. Both checkpoints are retained; the baseline was not replaced.
